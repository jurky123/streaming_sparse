# E35-A：交换候选召回与稀疏验证前的收益上限

**结论：Top-8能较常包含正收益动作，但未覆盖预登记要求的大部分高收益动作；停在A，不执行E35-B精确Key验证。**

## 范围与评价规则

仅重放冻结E29在原Risk初始状态的Medium512个动作分数与真实Q64收益。模型种子17/29各288事件，来自同样两条开发轨迹。没有读取原始QKV、执行Attention、运行Reader、训练、修改β或访问Test。Independent顺序由已保存的预测响应/质量/摘要中心计算，不获取新信息。

按预测分数降序取Top1/2/4/8，精确平局用原面板下标；即使预测分数为负也保留候选，避免把召回诊断混入接受门控。每个候选集的“收益”均为事后用真实标签选取最佳正收益或no-op，属于离线上限，不能称为线上执行结果。排序本身不读取标签。

恢复率=ΣTop-L最佳真实正收益/Σ原Medium最佳真实正收益。正收益机会与最佳动作命中率以Medium Oracle>1e−12的事件为分母：seed17为278，seed29为280。全288事件口径也在CSV。最佳命中容差1e−12；相对NMSE仅在初始J>1e−12定义。所有绝对汇总保留全部事件。

预登记参考门槛：两个种子Set Top8均≥70%恢复、且≥80%正收益机会。这是本轮对“大部分收益”的操作化标准，不是用户给定的精确阈值，也不是线上成功门槛；无论是否通过，本轮只执行A。

## 建议B的真实候选空间上限

分别取Set与Independent预测前2个动作。首先统计最多4个动作的去重并集；然后用其触及的已选页和未选页组成所有合法笛卡尔交换，与原Medium取交集。后者才是建议B的受限面板。两种上限均用原Medium为分母，未把受限Oracle当作100%的Medium收益。

|17|Four-proposal-union|41.52%|86.33%|3.597|4.958|6|5.755%|
|17|Touched-page-cartesian|43.72%|88.49%|5.778|4.958|6|6.060%|

|29|Touched-page-cartesian|43.47%|87.86%|5.590|4.906|6|5.565%|

理论上该方案最多8页、16个合法配对；本批数据实际最多6页，平均约4.9页。补充交叉配对只把恢复从约41%提高到约43%–44%。这43%–44%已经假设可以识别受限池内最佳真实动作并完美no-op；精确β验证仍保留有误差的预测响应与背景β，不能保证达到它。

受限池仍有一定剩余空间，不能由本实验断言任何验证策略都毫无价值；当前证据是不足以支撑“少数页验证即可恢复大部分Medium Oracle收益”。不据结果追加更大的L、重新设计候选池或执行B。
