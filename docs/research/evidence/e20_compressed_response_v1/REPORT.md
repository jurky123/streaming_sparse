# E20：低秩二阶响应压缩诊断

结论：本轮四个 BF16 配置均未通过“两例都保留至少80%完整 M2 收益”的预登记筛选。Value 单独压缩较好，主要观察到的损失来自这套固定 Key 基；这不能推断所有低秩 Key 表示都不可行。仅历史页增加统计又进一步损失收益，暂不进入正式缓存或 kernel 实现。

## 范围与选择规则

仅两个原始快照：city_walk/horse_field，seed101、chunk5、layer15、step0、head8、tile61。Q64/Page64、410页、41精确页、own保护、原Risk初始集合；完整14760个合法交换，另外保留共同面板。所有真实收益均用原始64 Query目标独立复核。没有新视频、训练或生产推理修改。

中心化 M2 在city与原M2同为11.2656%收益，但Risk未选页残差NMSE为0.45183，原M2为0.43824，因此依city独立规则锁定原M2。horse中心化收益7.3255%（原4.6041%）只报告，不反向更改形式。

Key基来自冻结layer15/head8 Key-response bank的QR前4/8列，不在快照拟合。Value使用现有basis的QR或E19训练集冻结的V-response PCA前8/16列。全128维a0保留；对称矩只存上三角。主结果使用实际BF16统计、FP32共享基，在FP64进行诊断收缩，不代表部署kernel精度或速度。

缓存为338历史页×12heads，不含原始KV、现有摘要、共享基、对齐和分配开销；不是替换原始KV的节省。读取账按72tiles×12heads扫描，真实缓存复用可能降低HBM读取，未实测。每Query每页主要矩收缩为8(1+rV)(rK+rK(rK+1)/2)+256rV FLOPs，另计共享Query投影；不含128维仿射项、exp、动作排序、访存和kernel启动。当前72页若新增统计需每步刷新，历史可commit复用。

本轮完整交换枚举仍是离线搜索，不是低成本在线路由。仅候选残差范数就至少约2×128×M×14760 FLOPs/head-tile，M16约0.0605 GFLOPs/head-tile、52.2 GFLOPs/层，尚不含其他动作运算。不能以小矩收缩成本代替完整路由成本。

## 核验和交付

原始M2评分与E19一致；联合FP64统计收缩与直接展开最大差≤1.12e-16；152个压缩阶段选中mask独立FP64目标复核，count/own通过。734个冻结数据文件及288个E13文件哈希未变。所有混合分母有效，无裁剪或删除异常候选。详见audit.json。

后续建议优先研究更合适的共享Key子空间；本轮不支持把这套低秩统计直接接入正式Streaming推理。只有两个同层同head快照，任何正负结果都不作总体泛化结论。

复现：先运行core.setup()，stage1分别指定两个event/device，然后select_form，compress分别运行两例，最后report。已有form_lock不可在观察horse后重选。全部脚本在local_experiments/e20_compressed_response/；完整统计缓存和评分保留在artifacts/e20_compressed_response_v1/compression/。精简包不包含原始QKV或可再生大张量。
