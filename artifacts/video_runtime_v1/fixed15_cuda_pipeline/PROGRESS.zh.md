# 固定 15% 精算的 SM80 融合注意力

本轮对照为首帧 24 页常驻、固定 15% 总预算、已启用预取与补偿布局的 base。105 帧比较使用 city_walk / 701，A100-SXM4-40GB；模块使用 horse_field / 2027 实际捕获的各窗输入。四窗均为 12 个 head、4608 个查询。矩阵主项沿用 150.289 TFLOP/视频，逐窗匹配原生 Dense 吞吐的参照为 726.34 ms。

## CUDA 实现与归因

一个 CTA 处理一个 head 与一个 Q64，四个 warp 分别负责 16 行。在缓存写入时把 K、V 重排为 SM80 MMA B 操作数的 lane/fragment 顺序。每页只搬运一遍 K/V，整页双缓冲，当前页 QK、双项 AV 与下一页 cp.async 重叠。每个 warp 直接用 QK 累加器构造概率高低项，避免为 AV 跨 warp 读取概率。P432 孤立精算从 0.974 降到 0.861 ms（1.130×，173.946 GFLOP，约 202 TFLOP/s）。仅用原始 K/V 双缓冲为 1.040 ms；预排后直接由每个 warp 读 global 为 1.349 ms；预排但逐页等待为 0.991 ms。三者的精算输出、LSE 与质量也都逐位一致。

补偿阶段每 16 页把代表 K、均值和三个 detail 的操作数合成一块，CTA 在 shared 中双缓冲。warp 内重排四个代表的概率形成系数，再做双项 AV。正常精算完成后，将结果暂存在该 CTA 的 shared 区域，复用原 K/V 缓冲做补偿。最终在同一核内投影 rank8 并按两侧质量合并，只写回 BF16 输出。异常 tile 通过标志触发既有在线软最大值回退。

要对齐原实现，分母需要按 lane 顺序逐项相加并按 XOR 2、1 归约，四代表系数也需沿用浮点加减顺序。rank8 投影使用原 tf32x3 拆分，低位残差沿用原机器码的位表示；TF32 的 K 片段按每 lane 相邻两项配对。仅调整到每 7077888 个输出差 1 个 BF16 值时，仍不能用模块误差推断视频轨迹。最终 paired_k.cu 在所有实测窗口和视频逐位对齐。

## 缓存代价与已测取舍

当前最快的试验适配器为 29 个稀疏层各缓存完整尺寸的 packed K/V，两份操作数共增加 4.588 GiB，另有跨层复用的摘要、输出和标志工作区。4.588 GiB 是由形状计算的缓存分配量。生产配置仍使用原来的基线。

- 双缓冲跨层预取仅保留两层大小的暂存区，但每步重排整个历史。用相同算术版本的 4 对单视频测试均变慢，中位约 164 ms。
- 在原 K/V 存储内原位重排，clean Dense 再按需还原到跨层复用的 162 MiB 暂存区。四窗、极端回退和视频均逐位一致。视频 4/4 变慢，中位约 85 ms。
- 将精算与补偿分两个设备核单独计算，或将补偿分成两个、四个部分最后合并，新增中间结果读写抵消了局部收益。直接放大补偿 Query 块也回退。
- 在新代表 K 排布中把同页概率放进同一 lane 可以省去系数交换，但改变了分母归约。显式恢复分母顺序后 P432 完整模块为 1.323 ms，慢于 1.302 ms 的配对 K 片段版。

- 只保留 V 的预排缓存可将额外 K/V 存储减半。单视频 6 对中位慢 1.48 ms。按 5 prompt × 2 seed 追加验证，7/10 更快，中位节省 3.50 ms，范围为慢 10.28 ms 至快 14.07 ms，10/10 latent 逐位一致。这个版本没有复现双操作数缓存的 42.77 ms 收益。原始数据见 multi_video/base.json。
- 将增量重排提前与摘要和路由并发，4 对逐位一致，相对生产中位节省 41.64 ms。按 8 或 128 个查询块合并异常检查后，P432 单独 guard 为 19.14 或 17.92 µs，原版为 18.43 µs。完整模块分别为 1.305、1.297 ms，保留原版检查。
- CUDA 版精算热循环的 PC 采样中，stall_wait 占 56,577 / 131,604，short scoreboard 占 7,751 / 131,604。等待集中于 MMA 依赖附近；精算独测已接近 Dense 的有效吞吐。整核要继续提速，应同时计入补偿和 76.51 ms 的配套工作。

## 复现

实验沿用项目虚拟环境和 PYTHONPATH=.。主核源码 paired_k.cu，以 nvcc -arch=sm_80 -O3 --fmad=false -lineinfo -Xcompiler=-fPIC -shared 编译。video_adapter_paired.py、pack_kernel.py、summary_fragments.py 和 repair.py 构成真实视频调用链。运行本目录 reproduce.sh module 或 reproduce.sh video 可重测真实输入或六对单视频。四个捕获输入的生成脚本为相邻 fixed15_baseline_v1/capture.py。模块 JSON 保存采样序列，paired_video/base.json 保存配对结果，paired_timeline.json 记录逐 chunk 事件，headline.json 与 paired_dense.json 汇总不同口径。
