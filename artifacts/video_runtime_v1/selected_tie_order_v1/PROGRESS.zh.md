# 相同 Risk 分数下的页顺序

base 满窗口 profile 在 116 次路由上执行 232 次 CUDA gatherTopK。第一次按 128 个槽位排序得到固定 10% 集合，第二次在掩码外填负无穷，再对所有 432 页排序取 43 个 ID。完整路由模块直接复用第一次的 ID 前缀，可省 9–12%，但 base 完整视频最大 latent 偏差达 6.117。已定位第一次分歧在 chunk2、layer12、step1、head7、tile19。两个实现的 Risk 和 mask 完全相同，页 105 和 157 的 FP32 分数都是 10.089183807373047，第二次排序改变了两页的相对位置。精算按顺序累加，此处必须还原。详见 ../reuse_selected_ids_v1/trace.json。

新实现只检查已入选页的相邻分数。存在并列时，在同一个 warp 内重建 CUDA gatherTopK 输入的页遍历顺序和原生小排序的并列规则。21、28 页使用与原生一致的 bitonic 比较，36、43 页按原生稳定排序的页序处理。执行 Full_Pset 交换的事件沿用原先的排序。12 组并列压力测试覆盖 4 种窗口和 3 种离散度，与原生二次 topk 对比，每个 ID 完全相等。实输入完整路由的 5 个输出张量也全部相等，216、288、360、432 页的加速分别为 1.115、1.096、1.101、1.112×。原生 sort 的紧凑重排对照见 ../compact_selected_order_v1，直接取前缀的失败对照保存在 ../reuse_selected_ids_v1。

单 tile 复用 attention 输出的独立验收在 ../direct_output_v1。完整模块 1.013–1.023×，三档视频 10 对各自节省中位为 16.9、12.1、14.6 ms，30/30 对 latent 字节相同。与并列处理合用的验收数据在 ../tie_direct_v1。
