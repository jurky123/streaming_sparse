# 精算选页顺序和跨查询复用

用 horse_field / 2027 四个实际窗口比较正式 CUDA 主核，每个窗口 20 对交替测量，每个样本重放 8 次。保留查询自身页作为第一个精算页，接续首帧 24 页。测试一仅把剩余精算页按页号递增访问；所有查询的集合与正式路由完全相同。测试二保留原有访问次序，packed K/V 采用 [头,432页,片段] 物理布局，同一头的相邻页从相隔 192 KiB 变为 16 KiB。两种输入都预先生成，计时只覆盖完整主核。[脚本](module.py) · [地址变换](head.py)

| 页数 | 页号排序加速比 | 排序前后输出 NMSE | 头主序加速比 |
|---|---:|---:|---:|
| 216 | 1.00045× | 4.02e−9 | 1.00263× |
| 288 | 0.99985× | 1.08e−8 | 1.00166× |
| 360 | 1.00014× | 2.20e−8 | 1.00135× |
| 432 | 1.00064× | 3.29e−8 | 1.00018× |

四窗均无回退。头主序四窗输出逐位一致。P432 复测的页号排序和头主序分别为 0.99988×、1.00087×，尚未计入生产方变更的成本。[排序复测](p432_repeat.json) · [头主序复测](head_p432_repeat.json)

P432 排序后，余下 39 个精算页之间的平均页号距离从 60.66 缩至 6.71。将同一头的 72 个查询块按精算序号对齐，每个位置平均涉及的不同页数从 50.48 降至 30.73。该统计反映逻辑访问次序，不保证 72 个 CTA 同时执行。NCU 的 L2 sector 命中率为 90.71% → 90.64%，DRAM 读 135.05 → 138.09 MB。实际路由的页序调整未改善满窗的缓存命中率。[计数](counters.csv)

另外做了一个仅用于定位瓶颈的人为对照。让每个查询块的 39 个附加页都取同一段连续的非锚点历史页，保留每次迭代数和主矩阵计算量。这会改变选页集合和模型输出。实测 P432 此时 DRAM 读从 134.17 降至 74.67 MB，L2 命中率从 90.84% 升至 95.00%，long scoreboard 从 3.31% 至 3.29%，Tensor pipe 活跃率从 65.72% 至 65.84%。配对主核加速比仍只有 0.99758×。在这个形状和捕获输入上，即使显著降低 DRAM 流量也没有换来主核速度。两个真实候选均停在模块阶段。[人为对照](common_p432.json) · [硬件计数](common_counters.csv)
