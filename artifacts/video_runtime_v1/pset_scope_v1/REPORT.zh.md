# Full_Pset：逐层、逐head、逐step收益与前1/4选择

本实验完成三个独立维度的单独开启测试，再实测三种选择规则（共5个组合方案）。所有结论限定在city_walk、seed701/702的短视频；两个seed既参与选择也参与组合验收，没有独立测试集。

## 1. 固定实验定义

- 9chunks、105帧、16FPS、768×512，history360（5个历史chunk）、tile72；Page64/Q64/R4、完整V均值+rank8、M16/B16、10%精算、16×32交换+no-op；当前全覆盖C_s17/Full_Pset_s17，M16入口开、G2关。
- 层测试：每次仅一个层的所有head、所有4个noisy step开启Full_Pset。head测试：每次仅一个head跨所有可修正层、所有4步开启。step测试：每次仅一个noisy step跨所有可修正层/head开启。其余位置均走C＋Risk。
- 可修正层索引1–29，共29层；模型层0原本固定Dense，因此Full_Pset无可开位置，其收益按结构为0，未改写为稀疏层。head索引0–11。noisy step索引0–3；clean step4只维护历史，不参加交换选择。
- 45个单维度设置×2seeds=90视频，加基础/完整档对照4视频=94；五个组合方案×2seeds=10视频。正式固定形状清单共104份视频，另有预热、计时重复及顺序检查。Dense复用已有city_walk对应两seed参考，只生成/解码一次。
- 排名收益 `gain = LPIPS(基础档, Dense) - LPIPS(单独开启, Dense)`，对两个seed等权平均；越大越好，相同收益按索引升序。SSIM/PSNR同步记录，未混成新的加权指标。
- 指标窗口[21,101)，LPIPS AlexNet和SSIM为256×384，PSNR使用原分辨率MSE。所有新视频采用相同TF32/cudnn设置。

## 2. 先解决常驻任务顺序的数值影响

首批自动动态编译结果中，先运行head-only任务再运行step3，与新进程直接运行step3得到不同轨迹，latent NMSE约0.20686。基础/完整控制仍与旧视频一致，所以只检查这两端不足以发现此问题。

直接四路对照：自动动态编译的两种顺序不一致；固定编译形状（static_route=True）后两种顺序逐位一致，并与此前step3结果一致。[顺序检查](order_check/summary.json)记录实际结果。首次结果、日志、排名和组合视频全部保留在`dynamic_order_dependent/`，不用于以下排名。

随后以固定编译形状重新执行全部94个排名视频、10个组合视频和正式计时。固定形状基础档与旧视频逐位一致，完整档与旧自动动态编译版本latent NMSE为8.6654e-5；因此本表完整档也重新生成，不混用旧质量结果。不是把旧排名套到新路径；这是本实验的统一数值控制。初次还触发默认编译变体上限，实验进程提升到64（累计512），没有修改数学、精度或学习权重。部署选定preset也强制固定编译形状。

## 4. 五种组合方案的实际结果

三种规则如下：分别按维度选前1/4得到层/head/step三档；三个选中集合取交集得到一档；将层/head/step独立收益相加，枚举29×12×4=1392个组合并取最高348个，得到第五档。相加使用同一LPIPS收益单位的原始边际收益，不额外按覆盖数归一化；三个轴原始覆盖面不同，这个分数不是经过校准的单个cell因果收益。所有组合都实际生成视频，不用相加分数代替实际质量。

生成时间：A100-SXM4-40GB，PyTorch CPU线程数2；seed701所有方案固定GPU6，seed702固定GPU7；各方案完整预热一次，3次计时取中位数，再平均两个seed中位数。排除IO、模型加载、编译和VAE，速度比为完整档平均生成时间/该方案平均生成时间。批量质量worker的单次时间不用于这张正式速度表。

head筛选仅让选中head进入在线Reader/交换，当前页面编码仍覆盖该层全部head；按层筛选同时减少需要维护编码的层数。因此相同评分预算不代表完全相同的额外时间。预算分母为1392个layer×head×step组合；实际短视频每个cell产生7个稀疏chunk×72tiles=504次评分。所有文件核对计数：完整701568，层前1/4为169344，head/step/相加组合为175392，交集10584。交集只有21/1392=1.51%预算，并不是25%。

## 5. 如何开启及实现位置

五个可复现配置保存在[presets/](presets/)。在当前stream基线命令中添加`--full-pset --pset-policy artifacts/video_runtime_v1/pset_scope_v1/presets/top_layers.json`即可；将文件名替换为top_heads、top_steps、intersection、additive_quarter可切换。benchmark、batch、worker均透传此参数；policy文件内容SHA进入identity，实际强制static_route=True。未修改全局默认完整档，不把这一个场景的筛选自动推广为部署默认。

- [runtime.py](../../../local_experiments/video_runtime_v1/runtime.py)：`set_pset_scope`和`set_pset_schedule`；逐layer/step选择当前修正；有修正需求的层在所有clean commit持续维护编码。
- [pipeline_graph.py](../../../local_experiments/video_runtime_v1/pipeline_graph.py)：Risk和基础mask仍覆盖全部head，仅选中head进入Reader/512交换，再把修改的mask写回；未选head保持基础LUT。图key包含选中head数量，索引存入GPU缓冲，任务间更新索引并复用同形状图。
- [deployment.py](../../../local_experiments/video_runtime_v1/deployment.py)：加载preset、固定编译形状、policy SHA；batch/worker/benchmark入口透传。
- [check_scope.py](../../../local_experiments/video_runtime_v1/check_scope.py)：head0/7/11及3-head组合的GPU输出契约；未选head和基础一致、所选与完整修正一致、事件数正确。
- [check_scope_order.py](../../../local_experiments/video_runtime_v1/check_scope_order.py)：任务先后顺序及静态形状对照。
- [scope_experiment.py](../../../local_experiments/video_runtime_v1/scope_experiment.py)：8卡常驻模型、45项单维度清单、两seed指标、三种规则的5项配置与组合验证。
- [scope_timing.py](../../../local_experiments/video_runtime_v1/scope_timing.py)：每seed固定一张GPU测量全部7方案。
- [report_scope.py](../../../local_experiments/video_runtime_v1/report_scope.py)：完整排名、对比表、preset和可视化。
