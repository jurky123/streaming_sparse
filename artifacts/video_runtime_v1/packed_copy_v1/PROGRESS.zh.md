# 正式 base 发布：跨页双项 AV 和合并输入重排

用户已接受跨页双项 BF16 AV。SM80 上 base 的 15% 页选择、clean 双布局写入及异常回退沿用已有路径。新主核把概率高低项分别累加到跨页结果。一个独立 CUDA 核用 ldmatrix 将当前 72 页 K/V、代表 K、均值及 detail 写成主核操作数布局，每次稀疏调用少一次启动。额外 K/V 缓存为 4.588 GiB。

## 正式三模式

同一张 A100-SXM4-40GB，city_walk / 701，105 帧，512×768，完整预热一次后计五次生成墙钟。各模式使用正式 accepted_tiers 入口。base 的 812 次主核、261 次 clean 双布局提交均得到确认。

| 模式 | 生成中位 s | 相对 Dense 的 latent NMSE |
|---|---:|---:|
| base | 5.16716 | 0.536715 |
| intersection | 5.21299 | 0.379339 |
| step | 5.87457 | 0.347492 |

正式 base 与用户接受的跨页候选视频逐位一致。intersection 和 step 各自与之前的正式输出逐位一致。新 base 和上一版 CUDA base 交替 6 对，6/6 更快，中位省 57.57 ms，范围 51.77–70.42 ms。相对旧 base 的 latent NMSE 为 0.22990，来自已接受的累加顺序变化。单独改变输入准备在 5 prompt × 2 seed 上 10/10 更快，中位省 11.90 ms，十组均逐位一致。该多视频试验在原累加顺序下进行，组合发布另做单视频验证。

## 模块与硬件

P216/288/360/432 的真实输入均核对了 packed K、V、摘要、标志及输出。P432 的准备从 71.81 降至 60.80 µs，含主核及回退检查的模块从 1.3018 降至 1.2868 ms；这组计时仅隔离重排改动。SM80 的 ldmatrix 同时处理 K 的正常片段及 V 的转置片段。NCU 显示全局读取请求从约 230 万 sectors 减至约 111 万，动态指令从约 1092 万降至 362 万。直接保留当前页的原生布局、按选中页在 CTA 内读取的另一个版本，在 P432 有 41.70% 的精算页访问当前页，模块从 1.300 升至 1.383 ms。这个方案止于模块。

组合发布的四种窗口都与已接受的候选逐位一致。在每窗极端输入上，864/864 个 tile 触发回退，并与原 Triton 在线回退逐位相同。输入准备原型和正式入口的配对原始数据分别位于 release_multi、installed_pairs；combined_pairs 比较两项改动合用后的正式路径与旧 CUDA base。

## 吞吐与理论口径

105 帧逐 chunk 设备时间线记录主核 823.24 ms、输入准备 38.87 ms、guard 8.54 ms，合计 **870.65 ms**。旧 CUDA base 设备累计为 934.48 ms。按历史 150.289 TFLOP / 726.34 ms 的固定参照，差额由 208.14 收窄到 144.31 ms。

按当前 CUDA 指令重算，补偿跳过完全被首帧覆盖的第一个 16 页块，三个 detail 双项 AV 均用 8 列输出。每个 warp 在每个精算页发射 192 条矩阵指令，每个实际补偿块发射 102 条。P432 另有最终 TF32 投影的 32 条，NCU 实测 51,743,232 条 Tensor 指令，与 (64×192+26×102+32)×3456 一致。沿用 QK/AV 主项范围，四窗合计 **147.510 TFLOP**，同形状 Dense 折算 **712.91 ms**。主核为 **179.18 TFLOP/s**，含输入准备与 guard 为 **169.43 TFLOP/s**，离这条参照还差 **157.74 ms**。末端 TF32 投影另计 0.184 TFLOP/视频。实测与原始运算计数见 release.json、combined_ncu.csv、combined_timeline.json。
