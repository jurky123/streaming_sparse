# 向下舍入 anchor 的 FMA 已成为正式 SM80 base

首帧 24 页继续计入固定 15% 精算预算。精算按首个选中页计算各行 anchor，取缩放后向下舍入的最大值。所有选中页使用 FP32 FMA 计算中心化 logit，再执行 exp2 和双项 BF16 AV。原质量 guard 和异常重算保留。

正式入口用同一张 A100-SXM4-40GB 依次运行三个模式。输入为 city_walk / 701，105 帧、512×768，每档完整预热一次，取五次生成时间的中位数。base 实际执行 812 次 CUDA 注意力和 261 次 clean 双布局提交。

| 模式 | 生成时间 s | 对 Dense 的 latent NMSE | 对前一正式版的 latent NMSE |
|---|---:|---:|---:|
| base | 5.16271 | 0.534783 | 0.356061 |
| intersection | 5.16782 | 0.379339 | 0 |
| step | 5.86161 | 0.347492 | 0 |

正式 base 的最终 latent 与用户接受的候选逐位一致。四窗的正常、单 tile 回退、全回退和单一主导键输入逐位一致。正式与候选主核的 3288 条 SM80 指令编码相同。该改动对前一版的净收益沿用八对交替验收的中位 8.22 ms，8/8 更快。候选视频设备时间线中主核从 819.70 降至 805.59 ms，按 147.510 TFLOP 对应 183.11 TFLOP/s，距 712.91 ms 的 Dense 同吞吐参照差 92.68 ms。含准备与回退为 853.85 ms。[正式计时及逐档误差](release.json) · [机器码比对](machine_code.json) · [配对计时与回退归因](../operand_delivery_v1/PROGRESS.zh.md)

## 以正式版本为对照的后续模块测试

P432 真实输入，全主核逐对交替，20 组，每组 8 次 CUDA Graph 重放。下表加速比按同一对取比值，再取中位数。输出及标志与正式版本逐位一致。

| 改动 | 三轮配对加速比 |
|---|---|
| 在精算归一化期间拷入首个需要的补偿摘要块，共用精算 guard 的 CTA 同步 | 0.9864、0.9865、0.9865× |
| 在常规指数范围使用简化除法计算精算输出与补偿归一化 | 0.9998、0.9995、0.9994× |
| 按 head 连续排列 packed K/V 页 | 1.0010、1.0009、1.0006× |
| 每 8 页一组，组内按 head 排列 | 0.9989×（一轮） |

布局测试预先排好操作数，只计主核。按 head 连续存放在 P432 的收益低于 0.1%，尚不足以覆盖生产写入路径变更的成本评估。上述变体均留在实验目录。[构建代码](build.py) · [模块测量](module.py)
