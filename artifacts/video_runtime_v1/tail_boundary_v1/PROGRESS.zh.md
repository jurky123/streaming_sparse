# 融合注意力的窗口边界与执行顺序

现有 105 帧时间线里精算与补偿融合核合计约 853 ms。在 432 页、43 个精算页、12 个头和 72 个查询块下，QK、双项 AV、均值与细节乘加的主项合计约 158 GFLOPs。普通 CUDA Graph 满窗口约 1.21 ms，折合约 130 TFLOP/s。

在 GPU7 预热后用 Nsight Compute 采一次当前部署内核。HBM 读 197.47 MB、写 38.92 MB，HBM 吞吐为峰值 10.41%，L2 吞吐为 21.53%，L2 sector 命中率 83.11%。Tensor Core 活跃率为峰值 42.14%，每 SM 理论最多驻留 8 个 warp，占上限 12.50%。真实选页索引共 37152 项，若每次都从 HBM 读取整页 K/V 需要 1217.40 MB；按每头页号去重后为 115.15 MB。硬件的 HBM 字节计数包括精算、补偿和输出。硬件计数这次耗时 1.461 ms，独立模块用 CUDA Graph 计时。[硬件计数](roof.csv) · [采集入口](profile_roof.py)

只对尾块保留边界掩码，以及将尾块 QK 缩为 32 个代表，都未得到收益。仅 216 和 360 页各有半块，分别最多省去该次补偿 QK 的 3.57% 和 2.17%（按填充后的代表数计），432 页无此空算。

预先传入每行选页掩码时，计时已排除掩码生成开销，直接读取仍较慢。把精算向量完整暂存于显存后，432 页编译器 spill 槽由 74 减至 16，BF16 输出相同，但每线程仍用 255 个寄存器，共享内存仍为 80 KiB，实测为 0.9749×。半向量暂存约 0.9780×。另以相邻 1、4、18 个查询块为组交错安排先精算或先补偿，结果见表。

这些候选均止于隔离模块测试。默认部署仍采用上一轮已通过视频验收的融合核。
