# SM80 base 复用提交之间的历史摘要

每个稀疏层保留一份按 MMA 操作数顺序排列的摘要。store 的提交计数、窗口页数均相同时，准备核只处理当前 72 页 K/V 和与当前页相交的摘要块。提交后第一次使用以及轨迹重置后走完整打包。P432 的 27 块中有 22 个完整历史块可复用，跨越历史与当前页边界的块每次刷新。发生 CUDA Graph 捕获的实例沿用共享工作区，每次全量准备，以适应回放期间没有 Python 调度的情形。[实现](../../../local_experiments/video_runtime_v1/fixed15_attention.py)

## 视频与显存

105 帧九个 chunk 的 812 次 CUDA 注意力有 609 次缓存命中。按每次命中的完整历史块计算，逻辑上少读写约 5.68 GB 摘要。正式准备时间从 39.15 降至 35.16 ms。融合主核为 735.59 → 734.86 ms，包含准备和回退的路径合计 781.53 → 776.83 ms。主核计数沿用 147.143 TFLOP，固定 Dense 等吞吐参照 711.14 ms，本轮距参照 23.72 ms。[设备汇总](comparison.json)

原型单视频 6/8 更快，配对中位省 5.44 ms，多输入 9/10 更快，省 6.52 ms。正式入口单独验收，city_walk / 701 八对为 5/8 更快，中位省 2.63 ms；5 prompt × 2 seed 为 7/10 更快，中位省 2.82 ms（1.00055×），范围慢 4.40 至快 11.58 ms。所有配对最终 latent 均逐位一致。正式入口的收益取正式配对记录。[单视频](release_video.json) · [多输入](release_multi.json)

29 层的常驻摘要缓冲共 199,646,208 字节（190.40 MiB）。独立正式 base 运行的 PyTorch 峰值分配为 14,221,277,696 字节，相对上一正式版本的记录增加约 175.03 MiB。workspace 和峰值的分配口径与缓存自身的大小不同。运行报告新增 packed_summary_bytes 与 packed_summary_hits。按优先采用较快实现的约定，本版已启用缓存。[正式运行统计与 latent 复核](comparison.json)

三档在同一张 A100 上完整预热后各跑五次，105 帧中位数为 base 5.09600 s、intersection 5.16087 s、step 5.87211 s。另卡独立正式 base 为 5.11734 s。后两档对该核的调用数为零。三档 latent 与各自上一版逐位相同，base 的 Dense NMSE 为 0.553556。

## 当前页输入的成本

单独计当前 K/V 的诊断中，P432 准备为 49.98 µs，全量准备为 62.08 µs。这项测量预填全部摘要，用来区分成本。仅改变准备核中当前 K/V 的 global 到 shared 搬运指令，P432 连同主核仅为 1.0010×，保留为诊断。P432 捕获中，每个查询块平均有 26.69/64 个精算页来自当前 72 页，每个头的 72 个当前页均至少被选中一次。若继续削减当前页打包，值得首先检查 K 的 RoPE 写出能否同时生成 packed K；直接跳过未选中的整页没有空间。[仅当前 K/V](kv_only_p432.json) · [实际页路由](current_routes.json)
