# Reader共享投影转换：本轮验收

基线为已逐位验收的A-only＋Reader两阶段＋旧RoPE，lazy回退关闭。权重、预算、候选、log质量、动作阈值均不变。将kernel逐Query读取FP64 mean/detail再转FP32，改为forward内先转换一次并共享。没有新增截断、低秩近似或低精度算术；但编译器的归约布局发生变化，结果不保证逐位一致。

完整筛查见../reader_vector_v1/REPORT.zh.md。向量拆分、寄存器上限、响应系数打包均未带来收益；仅共享转换在216/288/360/432页评分中有1.049–1.067×收益，包含转换成本。

理论：页面投影由64个FP64转为64个FP32，H12/P432占用从2.654MB降到1.327MB；72×16 Query复用同次转换。逻辑重复加载约少3.06GB，但大部分可能命中L2，不能把它当作HBM节省。向量kernel寄存器255→167；283MB的标量工作区不变。

数值定位：同输入候选端点center/rp和log状态逐位一致，仅页面加权汇总state不同，最大绝对差9.54e-7。因此固定输入差异来自归约计算顺序；视频差异是否由哪个离散动作放大尚未逐事件定位。
