# 满窗口的补偿指令成本与 BF16 系数复用

复用 P432 的九点诊断，在同一物理输入、相同 CTA 数和固定 NCU base 时钟下，交叉改变精算页数（32、48、64）及补偿块数（6、16、26）。取两个端点差值，再沿另一维取平均。输出检查覆盖全尺寸诊断核与部署核的逐位一致性。下表的指令数按每个 warp 折算，设备时间按一次完整调用折算。[九点入口](../phase_factor_v1/measure.py) · [NCU 原始记录](counters.csv) · [差分计算](slopes.py)

| 增量 | 时间 µs | 全部动态指令 | Tensor | ALU | FMA 管线 | LSU | XU |
|---|---:|---:|---:|---:|---:|---:|---:|
| 精算一页 | 15.29 | 614.09 | 192 | 186.07 | 96 | 88.02 | 32 |
| 补偿一块 | 11.42 | 741.25 | 102 | 238.50 | 278 | 72.50 | 34 |

按每条 Tensor 指令折算，精算和补偿分别需要 2.20、6.27 条其他指令。补偿的 FMA 管线指令密度分别为 278/102 和精算的 96/192，相差 5.45 倍。管线计数包含分配到该管线的运算，全核耗时还受发射重叠、依赖和调度影响。[差分明细](slopes.json)

为估计三个 detail 系数的构造成本，诊断核将均值的 BF16 高低项也送入三个 detail AV，保留三组 detail 数据读取、双项 MMA、后续累加及投影。数值语义随之改变，只用于模块定位。按四窗实际调用数加权，完整核合计省 7.05 ms，P432 加速 1.0099×。该数字包含编译调度差异。单独追求这段系数生成的优化收益有限。[诊断源码](detail_proxy.py) · [P432 计时及误差](detailproxy_432.json)

## 可部署语义的候选

在补偿的均值及三个 detail 系数中，保留成对舍入后的两个 BF16，用位操作还原为 FP32，直接计算低项残差。精算、掩码、双项 AV 和四代表的加减顺序沿用正式实现。[候选源码](reuse.py)

四窗每轮各 20 对 CUDA Graph 交替计时，每次计 8 次回放。首次按 P216、288、360、432 排列，完整核分别为 1.00361×、1.00429×、1.00409×、1.00438×。两轮测试按 116/116/116/464 次调用加权，分别省 3.31 ms 和 3.36 ms。四窗的输出、回退标志、回退重算均通过逐位检查，含全回退与单一主导键。P432 固定时钟的完整核从 1.32685 ms 降至 1.32026 ms，动态 warp 指令减少 1,375,488 条，Tensor 指令数相同。主要下降来自 ALU 管线。[P432 交替复测](coeffreuse_repeat_432.json) · [硬件计数](reuse_counters.csv) · [回退测试](guard.py)

同时加入上轮的寄存器掩码后，P432 为 0.9979×，四窗加权反而多耗 1.11 ms。该组合止于模块阶段。[组合候选](coeffmask_432.json)

## 视频验收和正式部署

105 帧 city_walk / 701 的前后融合核设备累计为 737.83 / 733.98 ms，省 3.84 ms。按当前 147.143 TFLOP 计算，候选为 200.47 TFLOP/s，达到固定 Dense 等吞吐折算参照 711.14 ms 的 96.89%，相差 22.85 ms。在同卡固定时钟的四窗模块对照中，按每 SM 周期归一化，P216/P288/P360/P432 分别达到各自 Dense 的 92.96% / 95.14% / 95.65% / 96.37%。[旧时间线](timeline_base.json) · [新时间线](timeline_coeffreuse.json) · [逐窗 Dense 对照](dense.json)

相同单视频的两轮独立交替计时分别 5/8 和 6/8 更快，中位节省 0.64 和 3.10 ms。波动触发 5 prompt × 2 seed 验证，9/10 更快，配对中位节省 3.87 ms（1.00076×），范围为慢 9.84 ms 至快 8.76 ms。全部 26 对 latent 与前一正式版逐位相同。[单视频](coeffreuse_video.json) · [独立复测](coeffreuse_repeat_video.json) · [跨输入](coeffreuse_multi.json)

SM80 base 已启用补偿系数复用。正式入口按源码哈希重新编译，六个 CUDA 核的全部机器指令编码与受测候选一致，主核为 3736 条静态指令。正式 base 验证 812 次主核调用和 609 次摘要缓存命中。三档同卡各完整预热后计 5 次，生成中位数为 base 5.08388 s、intersection 5.14447 s、step 5.84560 s。后两档均无该 CUDA 核调用。三档 latent 均逐位复现上一正式版，相对同一 Dense 输出的 NMSE 依次为 0.553556、0.379339、0.347492。[机器指令](release_sass.json) · [配对与正式三档结果](results.json)
