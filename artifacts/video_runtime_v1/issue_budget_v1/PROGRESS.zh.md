# 同卡时钟、指令发射和 CTA 收尾

在同一进程，按真实窗口交替预热 PyTorch Flash SDPA 和部署主核 30 次，然后用 Nsight Compute 采集各一次。每种时钟设置各用一张 A100，逐窗口在同卡上比较两核。每 SM 周期的主矩阵计算量按当前固定 15% 口径计算。下表为稀疏 / Dense 的有效吞吐。[采集脚本](profile.sh) · [计算与原始计数汇总](comparison.json)

| 窗口 | base 时钟，按耗时 | base 时钟，按 SM 周期 | 不控频，按耗时 | 不控频，按 SM 周期 |
|---|---:|---:|---:|---:|
| 216 | 92.43% | 92.46% | 106.00% | 91.54% |
| 288 | 93.87% | 93.90% | 73.14% | 94.03% |
| 360 | 94.36% | 94.88% | 74.03% | 95.10% |
| 432 | 97.12% | 96.76% | 74.82% | 96.18% |

不控频的 P432 采样中，Dense 和融合核分别为 1407 和 1095 MHz。P216 则分别为 1214 和 1406 MHz。单次 profile 的墙钟比值明显受频率影响。固定时钟的 P216 两核均约 1095 MHz，此时仍有约 7.5% 的每周期吞吐差。P216 / P432 稀疏核每单位主矩阵工作量分别只执行 Dense 的 89.4% / 87.0% 的 warp 指令；每调度器每活跃周期可发射的 warp 数分别为 0.42 / 0.43，Dense 均为 0.53。一次视频的 734.93 ms 仍按原视频时间线记录，两套实验分别保留。

为检查 CTA 调度，将全局计时器和 SM 编号写入每个 CTA 的独立槽位。对 864 个 CTA 连续采集 12 次。两端窗口的输出均与正式核逐位一致。P216/P432 的 CTA 数量最小值和最大值的中位数均为每 SM 8 个。最后一个 CTA 完成时刻与各 SM 最后完成时刻均值的差为 6.14 / 8.70 µs，约占插桩跨度的 0.86% / 0.64%。这个量衡量各 SM 收尾的不同步程度，不涵盖 SM 内部等待和中途空档。[P216](waves_216.json) · [P432](waves_432.json)

## 首页 anchor 的归约范围

针对短窗口的固定开销，只取查询自身页前 8 个键的行最大值作为缩放 anchor，64 个键全部参与精算；保留正式分母 guard、页集合与双项 AV。四窗各做 20 对交替模块测试，P216/P288/P360/P432 的加速比为 0.9946×、0.9942×、0.9943×、0.9923×。这四个捕获输入均无回退，最大绝对差为 0.0078125，输出对基线 NMSE 为 7.04e−9 至 1.43e−8。所有窗口耗时均增加，候选止于模块阶段，未变更部署。[候选源码](anchor8.py) · [P216](anchor8_216.json) · [P432](anchor8_432.json)
