# 补偿分支的归一化尺度

当前 base 已启用精算首页缩放和分母列累加。本轮保持精算与双项 AV，检查补偿分支在满窗口的 27 个代表块上逐次求最大值和调整分子、分母尺度的开销。固定尺度候选用精算 log2 分区函数减 4 作为补偿的初始对数尺度，避免逐块归约最大值；分母越出 (1e−20, 1e20) 时按原在线归约重算该块查询的补偿。其他候选改变归约宽度、合并两部分归一化、延迟求和，或在大幅偏移时动态更新尺度。

模块使用满窗口真实输入，其他窗口从同一输入取相应形状并对页号取模。CUDA Graph 预热后交替计时 16 对，每次重放 8 遍。表列成对加速比中位数。

## 同卡稀疏与 Dense 时间线

GPU7、city_walk / 701、同一主干，分别预热两种配置，再按段测 CUDA 活动。第 3–9 段每段有 116 次稀疏调用。用原生 Dense 与 base 的 FlashAttention 时间差估算被替换的 Dense 注意力时间，共 2618.23 ms；对应 base 融合核共 808.72 ms。主矩阵乘分别约 544.80 和 109.93 TFLOPs，后者包括双项 AV 与填充后的细节列。按每段 Dense 的有效吞吐折算，融合核约需 528.33 ms，和实测相差 280.40 ms。此估算忽略不同访存、非矩阵运算及回退成本，而且使用核累计时间，不能直接作为整条视频可节省的墙钟时间。[按段计算](attention_budget.json) · [Dense 时间线](dense_timeline.json) · [base 时间线](base_timeline.json)

仅 432 页进入视频验证，此形状约占已部署融合核 533 ms，按模块 1.007× 折算约省 3.7 ms。city_walk / 701 的新旧 latent NMSE 为 0.03465，前五段完全相同。对同一原生 Dense 的整条 latent NMSE 从 0.378409 变为 0.378474；RGB [21,101) 的 LPIPS 从 0.32924 变为 0.33025，SSIM 从 0.49696 变为 0.49581，PSNR 从 16.197 变为 16.173 dB。[Dense 误差](fixedguard/dense_error.json) · [画面指标](fixedguard/quality.json) · [并排视频](fixedguard/comparison.mp4)

单视频 3/8 对更快，配对节省中位数 -0.79 ms，加速比中位数 0.99984×；5 prompt × 2 seed 3/10 对更快，配对节省中位数 -1.77 ms，加速比中位数 0.99965×。本轮候选未通过视频速度验收，base 保留已接受的精算分母列累加。[单视频重复](fixedguard/single_video/base.json) · [多视频配对](fixedguard/multi_video/base.json)
