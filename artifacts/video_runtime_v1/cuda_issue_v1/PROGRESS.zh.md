# 固定 15% CUDA 融合核的跨页双项 AV 候选

同一页的 BF16 概率高、低项各做一次 AV。当前 base 从零开始计算一页的双项 AV，再把该页结果加到 FP32 输出。候选让同样的 MMA 指令直接累加到跨页输出，保留所有页、概率两项、分母计算、异常回退、补偿及投影。每页少了一次对完整输出向量的 FP32 加法，舍入顺序随之变化。用户已接受这一数值口径，正式 base 已启用该实现及后续逐位一致的输入重排。[组合版本验收](../packed_copy_v1/PROGRESS.zh.md)。

## 模块与硬件

采用 horse_field / 2027 的四种真实输入。CUDA Graph 每组重放 8 次，每种形状 20 组交替计时，两轮均获得同方向结果。四窗的主核配对加速为 1.057×、1.059×、1.058×、1.060×。P432 同卡复测为 1.2351 → 1.1658 ms，新增输出误差 NMSE 为 8.78e-8，最大绝对差 0.0078125，7,077,888 个 BF16 元素中有 26,986 个变化。guard 仍以原质量为判据。原始文件为 carry_P.json、first_carry_P.json、guard_P.json。

P432 同卡 NCU 测得 Tensor pipe active 从 55.69% 升至 59.12%，动态指令从 260,281,728 降至 238,156,416，依赖等待从 40.12% 降至 36.79%。同一视频的设备时间线中，融合主核累计从 869.90 降至 817.24 ms，主核有效吞吐从 172.77 升至 183.90 TFLOP/s。加上当前页 K/V 重排、摘要重排和 guard，稀疏注意力路径从 934.48 降至 877.97 ms，有效吞吐 171.18 TFLOP/s。计数口径为 150.289 TFLOP/视频。相对逐窗 Dense 折算的 726.34 ms 仍差 151.63 ms。

## 时钟归因与已测分支

在每个 CTA 同一线程采集阶段边界的 SM 时钟，864 个 CTA 取平均，15 轮取中位数。P432 的精算页循环占采样区间 75.0%，精算收尾 0.5%，补偿到均值/detail 累加完毕 22.1%，投影合并 2.4%。时钟版和正式核输出逐位一致，P432 墙钟 1.2467 对 1.2346 ms。周期份额是加仪表后的 CTA 局部时间，未覆盖启动与首个标记之前的操作。

- 下一页 QK 交错当前页 AV 的版本结果逐位一致，P432 0.950×。每页需要在读取下一页前等待，并在覆盖共享槽前同步。
- 页内边计算后续片段 QK 边转换此前的概率，逐位一致，0.957×。编译新增 88 字节 spill load 和 store。
- P432 固定形状特化与满块掩码简化，逐位一致，0.990×。
- 将精算结果按 lane 连续写入 shared，最终按 BF16 对写回，逐位一致，0.979×。NCU 记录的共享读冲突从 782,569 减至 170,349，写冲突从 690,781 减至 21,024。Tensor pipe active 同时从 55.62% 降至 54.41%。
- 仅把补偿均值也改为直接双项 MMA 累加，P432 为 0.993×。与精算直接累加同时使用时为 1.067×，比较对象均为正式 base。以下视频验收仅使用精算改动。

## 视频与质量

city_walk / 701，105 帧，6 对交替，使用同一份缓存、同一进程，全部更快。配对中位节省 50.48 ms，约 1.010×。每条视频有 812 次 CUDA 融合调用及 261 次双布局 clean 提交。没有修改 intersection 或 step 的路由与精度。

新旧 latent NMSE 为 0.22990，最后一个 chunk 为 0.69436。相对同一个 Dense，整段 latent NMSE 从 0.55755 降至 0.53671。在仓库规定的 RGB 帧区间 [21,101) 上，LPIPS 从 0.39093 降至 0.38422，SSIM 从 0.39709 升至 0.39989，PSNR 从 13.549 升至 13.723 dB。上述质量结论限于这个 prompt/seed。检视文件 /mnt/data/cuda_issue_v1/dense_base_carry.mp4，从左到右为 Dense、正式 base、候选。

复现本轮旧核时，先用 nvcc -arch=sm_80 -O3 --fmad=false -shared -Xcompiler=-fPIC 编译相邻 cuda_base_layout_v1/fixed15_attention.cu 至 /tmp/jzk_precarry_release.so。复现先在仓库根目录运行本目录 carry_av.py，再用项目虚拟环境和 PYTHONPATH=. 执行 CANDIDATE=carry python measure.py P、video.py --pairs 6 --save-pair /tmp/jzk_carry_video_pair.pt。quality.py 使用同卡同输入的 Dense latent，完整时间线见 timeline.json。tiers.py 使用正式 benchmark，三个模式每个先热身一条完整视频，再测五次。
