方法调研与选择依据

需要区分三个优化对象：删掉历史 token 会降低 KV 存储；保留完整 KV 但少算 QK 块主要降低注意力计算；复用静态区域还会减少后续层的 query/MLP 计算。这三类方法不能仅用一个“稀疏率”直接比较。下表列出本次核查到的代表性路线，并非穷尽所有论文。

方法及一手来源核心机制同模型可比性与本次状态
Light Forcing
官方代码		Chunk-Aware Growth 随生成进度分配稀疏率；Hierarchical Sparse Attention 先挑帧，再挑块。减少计算块，不直接压缩 KV 数组。已运行。同一 Self-Forcing 权重，完整官方长视频流程。论文包含微调；本次同权重移植不能代替其微调模型质量。
Forcing-KV
官方代码		离线 attention head 分类；空间头与时间头使用不同缓存；时间信息通过相似度进行动态选择。以 head 分组压缩缓存。已运行。官方 Self-Forcing head 分类文件和完整 grouped-KV 流程。保留官方较小的 1/1/1 context 配置，实际 KV 少于共同上限，单独列出。
DASA
官方代码		按层的相似度阈值和 token age 做历史 KV 筛选；保留最近参考帧；局部匹配后让静态区域复用特征、提前退出。已运行。启用两个免训练推理组件，非 DASA-KV 单独消融。没有加载可选 dynamics-guided distillation 微调权重，以满足同模型要求。
Deep Forcing
官方代码		Deep Sink 使用较大的前缀缓存（约一半），结合 temporal RoPE adjustment；Participative Compression 按近期帧关注度筛选历史 token。代码已下载并审阅，未计入本次实测。其长视频锚点和时间位置处理与此前讨论高度相关。源码存在 1560 token/帧、21 帧预算等固定假设，需要独立适配和核验。
LongLive 1.0
官方代码		Streaming sink + local window，面向长视频和交互式 prompt；官方在 2026-01-11 更新了 KV-cache relative RoPE。重要的流式基线，但使用自己的训练权重/LoRA。为保持相同 checkpoint，本次没有把原模型结果混入同权重表。dense 参考也不冒充 LongLive。
TriAttention
官方 AR 视频集成		基于 pre-RoPE Q/K 中心及范数的三角级数评分，压缩 LongLive 窗口内 KV；提供校准统计文件。有明确视频推理实现。默认针对 LongLive 权重和校准状态，移至当前 Self-Forcing 需另行验证/校准；本次仅调研。
MonarchRT
官方代码		用 Monarch 结构参数化稀疏注意力，配套 Triton kernel 和训练流程。官方也提供 training-free Self-Forcing 配置，不能说“必须训练才可用”。论文主要质量/吞吐结果与训练和 kernel 配置有关；本轮优先覆盖前三条互补路线，未运行此项。
FAST-AR
项目页		TempCache 利用跨帧对应关系压缩 KV；AnnSA/AnnCA 用 ANN 选择自注意力 key 和文本 token。论文可访问；本次检索未定位到可执行官方仓库，不将论文自报加速比写成当地实测。
Sparse Forcing面向 AR 视频的原生可训练稀疏注意力与 persistent block sparse kernel。核查时仓库为项目展示页，README 写明 checkpoints/code coming soon；没有可部署的推理代码。
HeadCast把 attention heads 分为 sink / dummy / global / spatial 等组，分配不同的上下文预算；提供 Self-Forcing 和 LongLive 推理入口。相关且可运行的候选。核查 README 的论文链接与作者列表尚为 TODO，当前仅按仓库说明介绍；本轮由 Forcing-KV 代表 head 分组缓存路线。
Ca2-VDM / CausalCache
官方代码		因果 temporal attention、跨去噪步 KV 共享、缓存队列与 cyclic temporal position embeddings。较早的 AR 缓存设计参照，基于 Open-Sora 体系。不是当前 Wan/Self-Forcing 同权重的直接替换，故不放入实测表。
SVG / SVG2 路线、Radial Attention、STA、SpargeAttention视频注意力的时空模式、局部窗口或内容感知块筛选。是重要的通用稀疏注意力参照，但原始任务主要包含双向视频扩散；接入 AR 缓存需要检查因果掩码、跨 chunk 上下文及长期误差，不能默认与原生 AR 方法等价。

本轮三项分别覆盖“按块少算”“按 head 压 KV”“按动态区域少算并压 KV”，因此比只选择几个相似的滑动窗口更能定位性能来源。Deep Forcing 与 LongLive 的位置策略是此前锚点设想的重要相关工作；这里仅说明关系，不加入新的 rebase 实验。

实验口径与原始实现差异

项目固定条件
模型Wan2.1-T2V-1.3B 结构；checkpoints/self_forcing_dmd.pt 的 generator_ema，所有方法 strict load。同权重 SHA256：a0413986d9734e02c09504e1520f5697ba6df731bb2f0f35577485e9cc8f56a3。
输入和生成三个场景 sailboat / skateboard / dog，seed=0；保存并注入相同初始噪声、每步 transition noise 和文本 embedding。四步去噪，[1000,750,500,250] 经官方 scheduler warp；context_noise=0。41 chunks × 3 latent frames=123，VAE 得到 489 RGB 帧，统一保留前 480 帧。
分辨率512×768，每 latent 帧 1536 个 token，兼容 Light Forcing 的 64-token block 与 Forcing-KV 的 6 个 patch 分组。此前 480×832 对应 1560 tokens，不能直接满足该 Light Forcing 核的分块要求。所有组一起改分辨率。
共同 KV 上限15 个历史 latent 帧（5 chunks）加 3 帧当前工作区，共 18 帧等价 self-KV 持久存储：5,096,079,360 bytes = 4.746 GiB。计算为 18×1536×12 heads×128 dim×K/V 两份×BF16 2 bytes×30 layers。
预算解释dense/LF 主 buffer 为 18 帧；DASA 主 buffer 为 15 帧，另外为官方 last_chunk_clean_k/v 留出最多 3 帧。Forcing-KV 保留原始较小配置，连未释放的 warmup 副本一起计数。它满足同一上限，但实际保留量不等；本次没有把其缓存扩大或人为填满。
存储统计范围逐次 generator forward 后按底层 storage 指针去重，计入当前工作区及额外长期 self-KV。上限不覆盖算子内部的临时 concat/clone、attention scratch、cross-attention 文本 KV；辅助特征状态和生成阶段 peak allocated CUDA memory（不含 VAE decode） 另外报告。因此这是持久 self-KV 预算，不是全程总显存硬上限。
环境与后端Python 3.10 / PyTorch 2.6.0+cu124 / Triton 3.2 / H200。环境没有 FA2/FA4，dense attention 统一替换为同数学语义的 PyTorch SDPA；LF 强制选用其官方 Triton 分支，防止缺 FA4 时悄悄 dense fallback。没有启用 FP8、LightVAE 或 TeaCache。
原始算法每个方法独立子进程，直接导入上游完整 causal model 与完整 inference pipeline。保留 head 分类、region reuse、cache update、native RoPE。除路径、token 尺寸、预算、兼容 backend 和固定输入外，DASA 需要下面说明的受限缓存管理修复。LF 的一个 Triton tl.sum(...,dtype=...) 改成先 cast FP32 再 sum，补丁单独归档。
方法参数LF：sparsity=.85、base=.95、keep_frames=3、keep_sink=1、keep_near=1、sink_size=1、long_video_gen=true；DASA：similarity=.95、search=3、dilation=3、KV shallow=.85/deep=.3、age=4；Forcing-KV：spatial/temporal/dynamic context=1/1/1、ar_start=1、num_frame_patch=6、sim_retention_ratio=.33，使用官方 Self-Forcing head 文件。
DASA 实现限制未修改官方代码在本次受限缓存条件下于第 11 个 chunk 越界：滚动分支混用全局帧位置和压缩后的局部 token 指针，且跳过正常 clean-KV 更新。补丁按完整 chunk 预留空间、FIFO 淘汰最旧保留 token、同步局部指针，然后继续原来的 KV 筛选/特征复用流程。保留阈值、token age、位置策略不变。这是带显式缓存管理修复的官方流程，不能称逐行零修改复现。失败日志保存在 sailboat/dasa.log.upstream_overflow；无溢出前缀与未修改版本核对见审计文件。
Forcing-KV 限制启用 dynamic temporal 时，当前代码把 temporal_context_length 限定为 1–3 帧，候选来自 3 帧。原始 1/1/1 配置的 KV 占用更小。不能把它解释为“实际 KV 量严格相等的消融”。
计时每个方法顺序运行，跨场景轮换次序；仍与其他任务共享 GPU。生成计时不含 checkpoint loading 和 VAE decode，含首次 shape 编译；另报第 7–41 chunk 的中位耗时。算法不同且后端非论文配置，不从本次数字推断论文级 kernel speedup。

评估定义与可解释边界

统一评估 RGB 帧 69–479，即 4.3125–29.9375 秒，减少初始缓存填充阶段影响。空间平均非线性 RGB 加权 (.2126,.7152,.0722) 得到全局亮度；相邻帧绝对差衡量全局亮度变化。短暗降为亮度低于中心 9 帧中值滤波的正差，固定统计超过 2pp 的帧数。它不等同于感知闪烁或物理亮度，正常光照和构图变化也会影响它。

色度为平均 RGB 除以通道和，分别记录相对自身开头和 dense 开头的漂移。DINO ViT-B/16 在 1fps 下计算全图特征，比较相邻秒与首帧的 cosine；Farneback 光流在 192×128、4fps 下计算并换算成像素/秒。这些描述量不替代主体追踪、人评或完整 VBench。原始逐帧序列、DINO 特征和脚本都保留。

相同输入不要求不同官方代码的首 chunk 输出逐位相同：RoPE 实现、低精度运算和 sparse kernel 都可能产生数值差异。报告记录首 chunk latent 相对 dense 的最大差值。每个方法的 checkpoint/input SHA、缓存上限和视频帧数则作硬断言检查。
